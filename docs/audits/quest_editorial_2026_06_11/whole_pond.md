- Disposition: EDIT (optional, low severity)
- Issues: terminology - title is "Clay Ball" but PF displays this variant's froglight as
  **"Clay"** (`block.productivefrogs.configurable_froglight.clay_ball` = "Clay Froglight").
  The census title should match PF's own display name for consistency with every other
  census entry. Cause: `title_case("clay_ball")` -> "Clay Ball" generically; PF special-cases
  the display name to "Clay".
- **Fix belongs in `tools/gen_completionist_chapters.py` (generated chapter)** - a direct
  lang edit would be wiped on next regen.
- BEFORE (generator, `title_case` at line 183-184; the census title emit at line 283):
  ```python
  def title_case(slug: str) -> str:
      return " ".join(w.capitalize() for w in slug.split("_"))
  ```
  (emits `quest.7F0CAF38409B6B3F.title: "Clay Ball"`)
- AFTER (add a display-name override map so census titles track PF's froglight lang; minimal
  form - a single special-case alongside the existing `ICON_OVERRIDES`/`VARIANT_RANK` dicts):
  ```python
  # PF display names that diverge from the generic title_case of the slug
  # (block.productivefrogs.configurable_froglight.<variant> in the PF jar lang).
  DISPLAY_OVERRIDES = {"clay_ball": "Clay"}

  def title_case(slug: str) -> str:
      if slug in DISPLAY_OVERRIDES:
          return DISPLAY_OVERRIDES[slug]
      return " ".join(w.capitalize() for w in slug.split("_"))
  ```
  (would emit `quest.7F0CAF38409B6B3F.title: "Clay"`)
- Severity note: cosmetic only - "Clay Ball" is unambiguous and the icon/task resolve
  correctly. Ship with the next regen if touching the generator anyway; not worth a
  standalone change.
