Current pin lives in [`CLAUDE.md`](../CLAUDE.md) Versioning targets and `pack/mods/productive-frogs.pw.toml`. Pull newer files with `packwiz update productive-frogs`; afterwards run `python tools/sync_instance.py` (with Minecraft closed) to mirror the jar into the dev instance.

Standing notes:

- PF ships **no slime-milk-bucket tag**, so the pack's `slime_milk_tags.js` (regex-built `#productivefrogs:slime_milk_buckets`) stays load-bearing for the End Cake recipe.
- PF is **CurseForge-only** (same FTB-stack constraint as the pack); `packwiz cf add productive-frogs`.
- When a bump changes item ids, recipes, or variant categories, run `tools/sync_instance.py` (so the new jar is local), `tools/gen_singularities.py` + `tools/gen_completionist_chapters.py` (both regenerate from the jar), then `tools/validate_quests.py` - the three-places audit is now **automated** (#101): Q-SINGULARITY-INGREDIENT diffs every singularity against the jar's `primer_item`, Q-DISSOLUTION-THREADING diffs the chamber rows (chain contiguity + the self-keyed law), and Q-SINGULARITY-COVERAGE / Q-VARIANT-MADE cover the coverage classes. The remaining MANUAL surface is quest LANG text (prose can't be diffed against a jar) and the crafting-table chain scripts.
